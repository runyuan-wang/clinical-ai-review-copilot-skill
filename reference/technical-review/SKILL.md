# 单篇技术审查

本模块可独立执行。先读实际可覆盖的原文，再逐项写：`问题｜原文位置｜状态（已证/未报告/待核/不适用）｜对结论的影响｜反证或替代解释`。不要把检查清单的存在当作缺陷，也不要把未报告改写成已实施或已失败。

## 先问研究是否测到了目标

核对患者级、时间、特征、标签/结局泄漏；输入是否在预测时点已可获得；训练/验证/测试是否按患者和时间隔离；同一队列是否重复进入多篇或多个分割。预处理、特征选择和调参是否只在训练折内完成，是否有 nested 疑问。记录事件数、类别不平衡、缺失处理、过拟合控制、模型选择和不确定性/CI。

## 再问验证与比较是否公平

区分训练、内部交叉验证、留出测试、时间验证和真正独立外部验证；外部验证本身也不自动高质量或临床有效。核对验证人群、标签、时间窗、数据处理和阈值是否一致。比较基线是否是临床现有做法、是否给出相同数据与调参预算；不公平比较只写为疑点，不能凭常识判定。

核对报告的不只 AUROC：区分能力、校准、Brier 等指标、CI、阈值下敏感度/特异度、决策或临床效用、人工复核、资源/延迟/实施影响。CI 重叠不自动代表等效，不重叠也不自动代表临床重要；小样本、失败或无显著性不能单独完成判断。

## 最后的边界

分别写：模型解释性不等于因果；相关不等于干预有效；内部高分不等于外院高分；外部验证不等于真实工作流获益；统计区分能力不等于校准、临床效用或公平。核对公平性、亚组、数据漂移、泛化和可复现性，但只能报告论文实际给出的内容。

推荐结尾：

```text
本次已核实：……（位置）
本次未报告：……（不能写成已缺失/已失败）
仍需回原文核对：……（具体位置）
因此最多支持：……
目前不能支持：……
```

清单是提醒，不冒充按正式手册执行的 PROBAST/RoB 偏倚评估，也不冒充 TRIPOD 报告规范符合性检查；TRIPOD 是报告规范，不是偏倚评分。不要生成总分代替作者和方法学审稿人的判断。
